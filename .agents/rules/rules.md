# Antigravity Production Protocol (초고속 완전 자율 워크플로우 엔진)

**[주의] 권한 엄격 분리 원칙 및 도구(Tool) 제약**
* **Master**: 기획 및 지시 역할. 오직 `docs/` 디렉토리 내의 파일 읽기/쓰기(Read/Write)만 허용된다. 소스 코드를 직접 수정하거나 개발 터미널 명령어를 실행하는 것은 절대 금지된다.
* **Worker**: 구현 및 실행 역할. 프로젝트 전체 파일 읽기/쓰기 및 터미널 명령어(컴파일, 패키지 설치, 빌드 등) 실행 권한을 가진다.
* **Reviewer**: 검증 역할. 엄격한 읽기 전용(Read-Only) 권한만 가진다. 소스코드 수정 절대 금지.
* **QA Evaluator**: 고속 테스트 실행 및 최종 시각/동작 판정 역할. 단일 CLI 자동화 스크립트 실행 권한 및 증적 판독 권한을 가진다.

---

## Ⅰ. 상태 신호 체계 (Signal Protocol)
모든 에이전트는 작업 결과 및 검증 단계에서 다음 3대 신호 중 하나를 반드시 명시해야 한다:
1. **PASS**: 검증 완료 및 승인. 사용자 개입 없이 다음 게이트로 즉각 자동 전진.
2. **FAIL**: 결함 발견 또는 테스트 불합격. 즉시 직전 정상 상태로 **자동 롤백** 후 재작업.
3. **BLOCK**: 환경 설정 부재나 치명적 오류로 인한 정지. 즉시 작업을 멈추고 Master를 호출.

---

## Ⅱ. 예외 처리 및 서킷 브레이커
1. **서킷 브레이커 (무한 루프 방어)**:
   - 동일한 이슈로 Reviewer 또는 QA 단계에서 **3회 연속 FAIL(반려)** 판정을 받을 경우, 작업을 강제 정지하고 사유 리포트를 작성한 뒤 세션을 동결한다.
2. **세션 동결 및 컨텍스트 보존**:
   - 세션 작업 진행 상태와 Todo 체크 현황을 `docs/`에 실시간 기록하여 언제든 중단 지점부터 재개할 수 있도록 한다.

---

## Ⅲ. 증거 기반 개발 원칙 (Evidence-based Rule)
- Worker는 `docs/02_todo.md` 항목을 완료할 때마다 **"수정한 파일의 실제 Diff 요약"** 또는 **"컴파일/린트 통과 로그"**를 근거(Evidence)로 명시해야만 완료 체크박스를 활성화할 수 있다.
- Reviewer는 해당 근거의 사실 여부를 대조 검증한 후에만 PASS를 발행한다.

---

## Ⅳ. 4단계 완전 자율 파이프라인 게이트

### Gate 1: 기획 단계 (Spec ➔ Planning)
1. Master는 요구사항과 제약 조건을 분석하여 `docs/01_request_spec.md`를 작성한다.
2. 명세 작성이 완료되면 소스코드를 건드리지 않고 Worker에게 작업을 자동 인계(Handoff)한다.
3. Worker는 명세를 기반으로 `docs/02_todo.md`를 작성하고, Reviewer가 Read-Only로 적합성을 점검하여 PASS 시 Gate 2로 자동 진입한다.

### Gate 2: 개발 단계 (Implementation ➔ Cross Review)
1. Worker는 To-Do 단위로 코드를 수정하고 완료 근거(Diff)를 남긴다.
2. Reviewer는 변경 사항을 대조 심사한다.
   - 반려 시: `docs/03_review_logs/`에 사유를 기록하고 FAIL 발행 후 재작업 지시.
   - 승인 시: PASS 발행 후 즉시 Gate 3으로 자동 전진.

### Gate 3: 초고속 원샷 통합 QA 단계 (High-Speed One-Shot QA)
에이전트와 LLM 간의 불필요한 대화형 핑퐁 통신을 제거하고 검증 지연을 방지하기 위해 반드시 다음 3대 고속 구동 원칙을 강제한다:

1. **대화형 브라우저 툴 호출 전면 금지 (Zero Multi-turn Tool Calls)**:
   - IDE의 대화형 브라우저 조작 도구(Open URL, Click, Inspect 등 턴 단위 호출) 사용을 일절 금지한다.
   - 브라우저 주소창에 `javascript:...` 형태의 스크립트/북마클릿을 주입하는 행위를 절대 엄금한다.
   - 모든 E2E 검증은 Headless 기반의 **단일 테스트 러너 스크립트(`node` 또는 `python`) 터미널 1회 실행**으로 완수한다.

2. **전체 엔드포인트/모듈 병렬 검증 (Parallel Execution)**:
   - 복수의 페이지나 컴포넌트를 검증할 때 순차 렌더링을 금지하며, `Promise.all` 등을 활용하여 대상 전체를 비동기 병렬로 동시 렌더링 및 검증한다.

3. **원자적 로컬 서버 생명주기 결합 (Atomic Lifecycle)**:
   - 스크립트 1회 실행 내부에서 **[기존 충돌 포트 강제 해제 ➔ 백그라운드 서버 기동 ➔ 병렬 렌더링 및 통신 검증 ➔ 증적(`docs/04_qa_evidence/`) 저장 ➔ 서버 즉시 Kill]**을 단일 생명주기로 처리한다.
   - 테스트 완료 후 포트를 점유한 채 대기하는 프로세스를 남기지 않는다.

4. **단일 턴 신속 판독**:
   - QA Evaluator는 스크립트가 일괄 생성한 `docs/04_qa_evidence/`의 캡처 화면과 콘솔 로그만 읽고 즉시 자체 판독한다.
   - **PASS**: `docs/04_qa_evidence/gate3_qa_report.md` 작성 후 Gate 4로 전진.
   - **FAIL**: 구체적 결함 사유를 첨부하여 Gate 2(개발)로 즉각 롤백.

### Gate 4: Wiki 및 완성 단계
1. Worker가 아키텍처 다이어그램 및 핵심 변경 사항을 `wiki/`에 경량 문서화한다.
2. Reviewer 최종 확인 후 Master가 전체 작업 완료 보고서를 작성하고 파이프라인을 종료한다.
